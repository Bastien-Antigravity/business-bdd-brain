# Feature: File Indexing Pipeline

## 🎯 Business Intent
- **User Story**: As an AI agent or developer, I want my workspace files to be parsed, chunked, enriched with AI summaries, and indexed into a searchable vector database so that I can perform semantic and keyword searches on my codebase and documentation.
- **Problem Solved**: Converts unstructured workspace files into semantically searchable knowledge chunks.

## 🎬 Scenarios (Gherkin)

### Scenario 1: Standard File Indexing
- **Given** a new or modified file in the workspace
- **When** the indexing pipeline processes the file
- **Then** the file content must be read
- **And** any previous chunks belonging to this file must be deleted from all stores
- **And** the file must be routed to the correct analyzer (Code or Markdown) based on its extension
- **And** the analyzer must return a list of standardized chunks with structural metadata.

### Scenario 2: Metadata Enrichment
- **Given** a raw chunk from the analyzer
- **When** the enrichment pipeline is triggered
- **Then** it must call the LLM service to generate a concise summary and hypothetical_questions
- **And** if the LLM is unavailable, it must fall back to a mock template and queue the chunk for background re-enrichment.

### Scenario 3: Multi-Store Persistence
- **Given** a fully enriched chunk
- **When** the pipeline stores the chunk
- **Then** the raw content must be saved to the SQLite Parent Store
- **And** the semantic embedding must be upserted to the PostgreSQL pgvector Store
- **And** the document text must be added to the BM25 Lexical Store for keyword matching.

## 🛠️ Technical Constraints
- **Format**: All stores must support the id format generated by the analyzers.
- **Resilience**: The LLM API failure must NOT block the main indexing flow.

## ✅ Acceptance Criteria (Definition of Done)
- [ ] Pipeline correctly orchestrates the flow from raw file to all 3 stores.
- [ ] Previous chunks are correctly pruned during re-indexing.
- [ ] LLM enrichment fallback and background queue behave as expected.
